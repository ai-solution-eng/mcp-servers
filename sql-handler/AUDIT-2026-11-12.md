**Scope:** the whole package at `/home/andrew/Code/HPE/SQLhandler` (v4.0.2, 31,870 lines in `src/sqlhandler`, 76 test files, 1,567 collected tests) plus its Helm chart, Dockerfile and release tooling.

## Headline

**2 P0, 13 P1, ~40 P2, ~44 P3, ~39 concrete enhancement proposals** (100 zone findings across 7 zones, deduped here).

Two things matter more than the rest:

1. **The policy engine's masking can be bypassed with one guessable identifier** — a caller under a column mask / row filter reads the raw rows by naming `__sqlhandler_base_1` in their own SQL. Reproduced end-to-end through `SqlEngine.query_duckdb`.
2. **Federated (`sources:`) deployments silently resolve every source to the global backend** — `os.environ` shadows every per-source field, and the chart renders `SQLHANDLER_BACKEND` unconditionally. Reproduced. Either the pod never boots (misleading OneLake error) or every source serves the global bucket under its own label.

Everything else is ordinary high-value defect work: a cache-key collision that returns another query's rows, a filesystem lockdown that defeats its own spill path, two auth gates that disarm in default configuration, and an `/api` data plane with no credential gate in the chart posture.

## P0 — fix before anything ships

### P0-1 [SEC] Masked/row-filtered tables are readable in the raw via `__sqlhandler_base_<n>`
`src/sqlhandler/engine.py:5485-5494` (registration), `:566-567` (same connection runs caller SQL)

```python
5488    base_name = f"__sqlhandler_base_{base_seq}"      # deterministic, starts at 1
5490    con.register(base_name, dset)                     # RAW dataset
5492    mask_sql = policy_mod.build_mask_select(base_name, columns, rule.column_masks, rule.row_filter)
5494        con.execute(f"CREATE OR REPLACE VIEW {view} AS ({mask_sql})")
```

The masking view is created over a registered relation whose name is deterministic and lives on the **same DuckDB connection** the caller's statement runs on. Nothing rejects the identifier: `sqlguard.assert_readonly` checks statement *type* only, `_referenced_tables` is a discovery heuristic, `_safe_ident` only quotes.

**Failure:** a caller in a group with `column_masks: {"ssn": "redact"}` and `row_filter: "kind != 'secret'"` runs
`SELECT b.ssn FROM work_order o JOIN __sqlhandler_base_1 b ON true` → raw SSNs, row filter gone. Inside the write tier the same statement persists raw rows into the caller's scratch root, so the leak outlives the request. Hidden tables are **not** affected (they register the empty relation).

**Lead verification — reproduced end-to-end** (`.scratch/audit-2026-11-12/p0repro.py`, real `SqlEngine` + fake provider + real policy file):
```
1. masked caller, normal SQL   : [{'id': 0, 'ssn': '***', 'kind': 'a'}, {'id': 2, 'ssn': '***', 'kind': 'a'}]
2. masked caller, JOIN base    : [{'ssn': 'ssn-000'}, {'ssn': 'ssn-000'}, {'ssn': 'ssn-001'}, ...]   <- RAW, and the 'secret' row is back
```

**Fix:** (a) reject `^__sqlhandler_` identifiers in `sqlguard.assert_readonly` (covers MCP + web + write payloads, ~3 lines); (b) also register the base under a random per-query suffix; (c) regression test asserting the two-name query is refused. (b) alone is obscurity — do both.

### P0-2 [BUG/DATA] Federation: `os.environ` shadows every per-source field in `SQLHANDLER_SOURCES`
`src/sqlhandler/config.py:20-22, 366, 447-468`; `helm/templates/configmap.yaml:35` vs `:93`

```python
22     return os.environ.get(name, default).strip()                      # _getenv: env FIRST
366    backend = _getenv("SQLHANDLER_BACKEND", e.get("SQLHANDLER_BACKEND", "onelake")).lower()
468    _, cfg = load_backend_config(src_env)                             # per-source dict = fallback only
```
```yaml
35   SQLHANDLER_BACKEND: {{ .Values.backend | default "onelake" | quote }}   # rendered UNCONDITIONALLY
93   {{- if .Values.sources }}   # ... "overrides the single backend"  <- false
```

Every `load_*_config(env)` treats the passed dict as a **fallback**; `os.environ` always wins. The chart always sets `SQLHANDLER_BACKEND`, so in a `sources:` deployment every source resolves to `onelake`.

**Lead verification — reproduced** (pollute env the way the chart does, then resolve a per-source dict):
```
per-source backend=s3  ->  resolved backend: onelake ; bucket: None ; endpoint: None ; access key: None
```
**Failure:** (a) sources-only install → every source builds a OneLake provider with an empty FabricConfig → boot fails naming the wrong backend; (b) migrated install (FABRIC_*/S3_* still set) → **every source silently serves the global bucket under its own label**, per-source credentials ignored. `documentation/FEATURES.md:51-56` promises "several buckets or sources of any backend mix"; `configmap.yaml:94` says it "overrides the single backend". Both false as shipped.

**Fix:** explicit-override semantics in `load_source_providers` (consult the dict first, `os.environ` only for keys the dict does not define) + a startup warning when a global var would have shadowed a source field. Add a test that sets the env and asserts per-source wins.

### Detail on the two executed P1s

**P1-1 — cache-key collision.** The scanner models only SQL-doubled quotes (`''`); DuckDB's `E'...'` strings use backslash escapes, so `\'` closes the scan-quote early and the whitespace *inside the real string* is collapsed.
```
A: SELECT E'a\'  b\'  c'   -> "a'  b'  c"     A norm: SELECT E'a\' b\'  c'
B: SELECT E'a\' b\'  c'    -> "a' b'  c"      B norm: SELECT E'a\' b\'  c'   COLLIDE: True
```
The result-cache key hashes the normalized text, so B is served A's Arrow table — a silent wrong answer, and the same function feeds the preview key and the shared L2. **Fix:** bail out on any backslash inside a quote (same as the existing `$`/comment bails) — one line.

**P1-2 — lockdown vs spill.** Same 50M-row sort, same 256 MB budget, same temp dir:
```
no lockdown   : OK (50000000,) in ~2.4 s          <- spilled to temp_directory
repo lockdown : FAIL PermissionException: File system LocalFileSystem has been disabled by configuration
```
On any k8s pod (cgroup detected ⇒ budget always applied) wide sorts/aggregations now hard-fail with a security-looking error, and the documented emptyDir remedy cannot work. **Fix (verified):** `SET allowed_directories=[temp_dir]` **then** `SET enable_external_access=false` — spill works, `/etc` and the k8s SA token stay blocked. Order matters; `allowed_directories` cannot be changed once external access is off.

## Cross-cutting themes

1. **Fail-open is the house style at the edges.** Every gate that can be "unconfigured" treats *unconfigured*, *empty* and *unreadable* as the same state: relay attribution (P1-5), the `/mcp` key store (P1-4), `/api` (P1-6), mask compilation (P1-3), `token_matches` (P3). The fix is a shared convention: *configured-but-unusable must fail closed with a distinct error*, never degrade to "no gate".
2. **The enforcement mechanism is visible to the thing it enforces on** (P0-1) — masking views on the caller's own connection, a deterministic internal name, and a guard that only checks statement type. Same shape as the catalog-write-as-auth-not-admin issue and the `/api` posture: the *intent* is right, the *boundary* is drawn one layer too shallow.
3. **Caching is where correctness goes to die.** Three of the top findings are cache-shaped: a key collision (P1-1), a missing volatility term, an accounting drift that starves L1, an L2 artifact that bypasses the memory budget (P1-10). The cache-key discipline is genuinely good (policy hash + throttled snapshot versions); the *inputs* to the key are the weak spot.
4. **Docs are unusually good — which makes the false claims stand out.** `FEATURES.md`, `MCP.md`, `CONFIGURATION.md` and `SCALING.md` are specific and mostly accurate, so the exceptions (spill, `/api` token wiring, relay "never authorization", fastrender, sources "any backend mix") are actively misleading. Each is listed with its finding.

## What is genuinely solid (verified, keep)

- **`sqlguard` held up** under a 35-statement battery: DDL/DML, ATTACH/COPY/EXPORT/INSTALL/LOAD/SET, `CREATE SECRET`, CALL, CTE-DML, multi-statement, EXPLAIN-wrapped DML — all refused; only a parenless-rewrite hole with no live payoff. *(z1)*
- **Cache identity discipline is right**: the result key carries the policy hash + throttled per-table snapshot versions; masked and unmasked callers never share an entry; virtual materializations are policy-partitioned; enforcement-off keys are byte-identical to the historical format. *(z2 verified the term list; z5 confirmed the masking-view path)*
- **`WriteLease` is now correct** — random token, release only on token match, `_break_stale` requires past-TTL + provably-dead same-host pid + a token/inode re-check; URI/UNC roots refused. The prior P0-6 double-writer is closed. *(z5)*
- **Broken-first policy fails CLOSED** via a sentinel that hides covered tables and takes its own cache-key space; `default_group` is required when groups exist. Prior P0-2's fail-open is gone. *(z5)*
- **XSS is clean**: all 45 `innerHTML` sinks in the UI escape server data (`esc()` or `textContent`), including results, schema, saved list, inspector output and both highlighters. *(z4)*
- **Middleware layering is correct** (LIFO verified), the transport guard holds, and the D19 claim ordering is right; `/mcp` auth is mandatory in the chart and the pod fails loudly rather than booting open. *(z3)*
- **Chart hardening defaults are good**: `hardened: true`, non-root uid 1000, `readOnlyRootFilesystem`, `automountServiceAccountToken: false`, `/tmp` emptyDir wired, runtime-only deps (no compiler, no ODBC repo), plus render-time `fail` guards for policy-with-no-source, mountPath overlap and RWX-required-for-replicas.
