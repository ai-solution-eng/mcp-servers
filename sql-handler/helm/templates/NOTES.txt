════════════════════════════════════════════════════════════════════
1. MCP API key — REQUIRED BEFORE THE POD WILL START.
   BREAKING CHANGE (2026-11): /mcp auth is now MANDATORY, the same
   posture as applygate/k8s-mcp. SQLhandler reads the WHOLE data lake,
   so the chart wires MCP_API_KEYS from an operator-created Secret
   UNCONDITIONALLY — until the Secret below exists in this namespace
   the pod sits in CreateContainerConfigError (by design, not a bug).
   The chart NEVER creates the key Secret (an envsubst apply once
   emptied a live key Secret — the K8S-MCP lesson). Create it first:

  kubectl -n {{ $ns }} create secret generic {{ $secret }} \
    --from-literal="api-keys=$(openssl rand -hex 32)" \
    --dry-run=client -o yaml | kubectl apply -f -

   Read it back:
  kubectl -n {{ $ns }} get secret {{ $secret }} -o jsonpath='{.data.api-keys}' | base64 -d

   ROTATION: the value is a COMMA-SEPARATED list of valid keys —
   append the new one, move clients over, drop the old. The SERVER
   re-reads its env per request, but Kubernetes does NOT update a
   secretKeyRef env var in a running pod, so the edit only takes
   effect after a rollout:

  kubectl -n {{ $ns }} rollout restart deploy/{{ $name }}

   For true no-restart rotation, mount the Secret as a volume and
   read the file per request — that is a chart change, not a value.

   LOCAL-DEV ESCAPE: --set security.apiKey.openMode=true leaves the
   env unwired so /mcp runs open (loud startup warning). Off by
   default; never use it for a deployment anyone else can reach.

════════════════════════════════════════════════════════════════════
1b. SECURITY POSTURE CHANGED (audit 2026-11-12) — read before upgrading.
   * ANONYMOUS CALLERS ARE REFUSED by default: the chart now sets
     SQLHANDLER_REQUIRE_IDENTITY=1, so /api/* (the REST twin of run_sql
     that reaches the same lake) and /mcp return 401 without a credential.
     /health, /ready, /ui, /api/whoami and /oauth/* stay open.
     -> A browser user needs an SSO cookie or a pasted API key; a direct
        in-cluster caller needs X-API-Key. Opt out ONLY if the gateway
        authenticates every caller and nothing else can reach the pod:
        --set security.identity.requireIdentity=false
   * /metrics and /ready are still OPEN by default. Turning on
     security.metricsAuth now REQUIRES metrics.podMonitor.bearerTokenSecret
     (the render fails otherwise, because an unauthenticated scrape target
     fails silently in Prometheus).
   * The AUDIT TRAIL is chart-wired: security.audit.enabled=true needs a
     durable claim (security.audit.existingClaim or .pvc.create); the render
     refuses an ephemeral trail.
   * Egress can now be restricted: security.networkPolicy.egress.enabled
     (default off) renders default-deny egress + DNS + your CIDRs.

════════════════════════════════════════════════════════════════════
2. Endpoints — /mcp REQUIRES the key (X-API-Key or Authorization:
   Bearer); /api/* requires an identity (see 1b) and honours
   SQLHANDLER_API_TOKEN when set
   (set it to enable), the read-only UI and the probes stay open.
  kubectl -n {{ $ns }} port-forward deploy/{{ $name }} 8001:9097
  Console : http://localhost:8001/        (read-only UI)
  MCP     : http://localhost:8001/mcp     (X-API-Key: <api-key>)
  Probes  : /health /ready /metrics (always public)

  MCP client config:
  { "mcpServers": { "sqlhandler": { "type": "remote", "url": "http://<host>/mcp", "headers": { "X-API-Key": "<api-key>" } } } }
