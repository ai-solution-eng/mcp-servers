sqlhandler {{ .Chart.Version }} deployed to namespace {{ $ns }}.

════════════════════════════════════════════════════════════════════
1. MCP API key — OPTIONAL (auth is OFF until you enable it).
   By default /mcp runs OPEN (the chart wires no key env) and relies on
   the gateway / network position; /api/* keeps its separate
   SQLHANDLER_API_TOKEN middleware (set SQLHANDLER_API_TOKEN to enable
   that one). To turn on the /mcp key gate — the chart NEVER inlines a
   key in values:

  kubectl -n {{ $ns }} create secret generic sqlhandler-apikey \
    --from-literal="api-keys=$(openssl rand -hex 32)" \
    --dry-run=client -o yaml | kubectl apply -f -
  helm upgrade <release> . -n {{ $ns }} --reuse-values \
    --set security.apiKey.existingSecret=sqlhandler-apikey

   ROTATION (near-zero downtime once enabled): the value is a
   COMMA-SEPARATED list of valid keys — append the new one, move
   clients over, drop the old. The secretKeyRef env is frozen at
   container start: the new list reaches the pods via a ROLLOUT (the
   chart's checksum/secret annotation automates it on the next helm
   upgrade; between the Secret apply and that upgrade the pods keep
   authenticating with the OLD list). The fleet-universal MCP_API_KEYS
   env is honored too (either var works).

   DATASET ACLs: mint a per-identity key with `python scripts/mint_key.py`,
   append it to the same Secret (a Secret append reaches the pods via the
   checksum-annotated rollout above), and add its fingerprint assignment
   (key:sha256:<fp>) to the policy ConfigMap's datasets.assignments — the
   policy file hot-reloads on mtime (see documentation/DEPLOYMENT.md §4.7.1).

════════════════════════════════════════════════════════════════════
2. Endpoints:
  MCP   : /mcp   (X-API-Key: <api-key> — only when enabled)
  API/UI: /  and /api/*  (SQLHANDLER_API_TOKEN when set)
  Probes: /health /ready /metrics (always public)
  MCP client config (when enabled):
  { "mcpServers": { "sqlhandler": { "type": "remote", "url": "http://<host>/mcp", "headers": { "X-API-Key": "<api-key>" } } } }
